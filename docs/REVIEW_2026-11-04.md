## 1. What the audit found and what was fixed

### 1.1 Critical (would have produced wrong data or a crash in normal use)

| # | Finding | Fix |
|---|---|---|
| A1 | **Sticky auto-resume recorded silence all night.** After process death, the START_STICKY restart auto-started capture from the background; on Android 11+ a background-started mic FGS gets no while-in-use microphone access — `AudioRecord` returns zeros without erroring, so the night "completed" empty. (`MonitorService`) | Null-intent restarts never start capture. Decision extracted to `StartIntentPolicy` (+ tests). A new high-priority `InterruptedNotification` offers a **Resume** action (a user tap = the interaction that grants mic access), resuming into the same session with the existing statsCarry/markResumed plumbing. |
| A2 | **`stopSelf()` before `startForeground()` after `startForegroundService()`** — the classic `ForegroundServiceDidNotStartInTimeException` crash on the pre-flight-bail paths (revoked mic, <500 MB storage), reachable from Home. (`MonitorService`) | `startInForeground` promoted to the top of `beginRecording` before any early return; bails call `stopForegroundStop()` first. Reviewed and refined (see §3 R1/R2): no promotion at all on API 34+ without RECORD_AUDIO (type-less promotion throws there), 0-type promotion kept below 34. |
| A3 | **Event loss in `EventDetector.deferOrFold`.** A closed draft arriving while a same-type final was still held and beyond `mergeGapMs` was silently discarded (the KDoc claimed the branch unreachable, but expiry's busy-cap makes it reachable — hand-traced). (`EventDetector`) | The successor is now stored as the new deferred final; regression test reproduces the exact trace (fails on old code: emits 1 event instead of 2). |
| A4 | **Garmin re-import duplicated every measurement.** `importForDate` upserted raw payloads but always inserted new measurement rows — tapping Import twice doubled every vendor metric on the report. (`GarminImportManager`/`MeasurementRecorder`) | Delete-then-insert inside one transaction, scoped to the metrics actually present in the batch (a partial re-import never wipes other metrics). Pinned by `MeasurementRecorderTest`. |
| A5 | **`RetentionWorker` orphan sweep could delete in-flight clips** during an active night (file exists between `writeClip` and the DAO insert; WavWriter writes directly to the final path). | Sweep gated by `OrphanSweepPolicy` (skip while any session is open; only files ≥ 1 h old), both pure and unit-tested. |

### 1.2 Correctness (smaller windows, real consequences)

- **`AudioEngine` init was outside the try/catch** — an OEM `AudioRecord`-constructor throw killed the whole process overnight; now routed to `onCaptureError` → session finalizes INTERRUPTED (`AudioEngineInitErrorTest`).
- **Thermal throttling could evict all event audio from a persisted clip**: while throttled, stamps advance 1.0 s, so the maxHold emission could land exactly on the 8 s ring horizon. Emission caps are now stride-aware (bit-identical at the normal 0.5 s stride — pinned by test), and the engine refuses + does not budget-book a clip whose ring no longer holds the event's end (`RingBuffer.holdsEventAudio`).
- **Non-transactional multi-step writes**: `insertEvent` (clip→event→backfill) and `FactorLogRepository.saveForDate` (delete→insert) are now `withTransaction`-wrapped.
- **`HomeViewModel` init race**: `Interrupted` could clobber `Recording` when a restart was mid-flight; re-check after the suspend read + new `canFinalizeInterrupted` guard (finalize refuses unless Idle/Interrupted).
- **`RingBuffer` int overflow after ~37 h** (negative `toInt()` → `NegativeArraySizeException`): clamped, boundaries tested via a pure seam.
- **Garmin garbage first window / failed reads**: `fillBlocking` no longer analyzes a window after a failed read.
- **AGC disable didn't survive release** on some OEMs: effect instance now held for the engine's lifetime.
- **Config incoherence**: `EventDetector` now receives the engine's actual `windowMs`/`hopMs` (both engines identically — replay-matches-live preserved and pinned).
- **`WavReader` unbounded allocation** on a corrupt header (could OOM the eval harness): size bounded against file length.
- **FixtureEvaluator accounting**: missing files / decode failures / rate mismatches now counted distinctly (JSON gained `missing_files`/`decode_failures`/`rate_mismatches`).

### 1.3 Robustness & hygiene

- `GarminClient`: accepts any 2xx (empty body → absent result), one short-backoff retry on IOException per endpoint; token/401 logic untouched.
- `GarminKeyStore`: a corrupted blob (`AEADBadTagException`) now clears itself so `hasKey()` stops disagreeing with `load()`.
- `UserPreferences`: retention days clamped 1..365, schedule minutes 0..1439 — at the setter **and** the read (legacy stored values safe).
- `deleteNight` and `deleteAllData` now also delete session logs (nothing about a deleted night outlives it).
- `finalizeOpenAsRecovered` counts successes, not attempts; dead `recoverOrphanSessions` removed; stale comments fixed.
- FGS recording/delay notifications got `contentIntent`; thermal status is applied to a freshly created engine (previously unthrottled until the next status *change*); `InterruptedNotification` is cancelled on stale-resume and after banner finalize; a redundant START while recording no longer resets the FGS chronometer.
- POST_NOTIFICATIONS denied no longer means scheduled recording silently never starts: Settings gained a notifications-denied warning row + fix button (mirrors the exact-alarm pattern).
- Remaining hardcoded English strings moved to `strings.xml` (mic indicator, cancels, back buttons, key-store error, service errors); `SessionLogScreen` no longer reads files on the main thread.
- ACTION_RESUME is now gated by the master **Recording enabled** switch (same as manual/scheduled starts) — decision documented in the KDoc.

### 1.4 Tooling / build

- **The project was not a git repository** (README even says `git clone <repo-url>`). `git init` was run and a **baseline index staged before any edits** — the whole change set is reviewable via `git diff` (worktree vs index). **No commit was made** (that's yours to make: `git add -A && git commit` with e.g. `fix: audit-hardening pass across capture, data, service, UI, tooling`).
- `.gitignore` gained `.kotlin/`, `.pytest_cache/`, `.ruff_cache/`, `.venv/`, `.zcode/`.
- **Python tools now have a reproducible env**: `pyproject.toml` (uv-managed, pytest + ruff dev group, `testpaths=["tools"]`) + `uv.lock`. `uv run pytest` just works.
- **`night_loudest.py` was silently corrupting pulled data**: it used the pty-mangling `adb shell … cat` transfer that `export_fixtures.py` had already fixed (CRLF-mangled SQLite opens but yields corrupt rows). It now imports the verified exec-out + byte-count + RIFF-check helpers; 3 new tests cover the failure paths.
- Release builds: `signingConfigs` wired from env vars only (`RELEASE_STORE_FILE/PASSWORD/KEY_ALIAS/KEY_PASSWORD`) — no-op without them, no secrets in the script.
- Stray zero-byte file `SELECT COUNT(*) FROM acoustic_event WHERE sessionId=6;` (shell-redirect accident) deleted.
- Docs de-staled: STATUS.md headline (92→287 tests, v6→v7), README schema line; README's START_STICKY description rewritten to the new (non-silent) behavior.

## 3. Independent review of the fix diff (and what it caught)

The reviewer pass found **1 P0 regression and 5 P1s in the first fix wave** — all fixed and re-verified (this is why the second pass exists):

- **R1 (P0):** the new sticky-restart branch itself called `stopSelf()` without `startForeground()` — the exact crash class A2 fixed, on the most common overnight path. Now promotes first, then removes the FGS notification before `stopSelf()` (the interrupted notification survives).
- **R2 (P1):** type-less `startForeground` promotion does **not** avoid the API 34+ `SecurityException` (verified against decompiled androidx.core 1.15.0: type 0 passes straight through and resolves against the manifest). Version-split implemented: no promotion on 34+ without mic permission; 0-type below 34.
- **R3–R6 (P1):** interrupted-notification not cancelled on all paths; ACTION_RESUME bypassing the master switch (now gated — decision recorded); Garmin partial re-import wiping previously imported metrics (now metric-scoped); redundant START resetting the FGS chronometer.
- **Verified clean** by the reviewer: stride/hold-cap arithmetic (unthrottled path bit-identical), transaction shapes (Room-generated sources checked), replay-matches-live, signing no-op without env vars, pytest import mode, notification id/channel/PendingIntent uniqueness, no secrets.
