# 8. Garmin and Health Connect

**Scope:** `app/src/main/java/com/sleepanalysis/data/garmin/` (GarminClient, GarminImportManager, GarminJsonParsers), `data/healthconnect/HealthConnectImportManager.kt`, `data/secure/GarminKeyStore.kt`, the import code paths in `ui/settings/SettingsScreen.kt` (key status/save, dated imports, permission launcher, state rendering), the automatic backfill in `ui/report/ReportViewModel.kt`, and the retry budgets in `data/prefs/UserPreferences.kt` plus the matching tests. Table definitions: see section 4. The report's use of the imported values: see sections 5–6. The rest of the settings screen: see section 9.
**Requirement prefix:** GRM — rows in N.3 are numbered `GRM-01`, `GRM-02`, …
**Status values:** `tested` = a unit/instrumented test asserts it (cite it) · `device-verified` = evidence from a real night or device run exists (cited) · `unverified` = implemented, no test and no device evidence · `not implemented` = designed or documented only.

## N.1 What the user gets

1. The user can paste their Garmin Personal API key once; it is encrypted with an Android Keystore key and only ever shown back masked as its last 4 characters. [GRM-01, GRM-03]
2. The user can delete the key; the status reverts to "no key stored". [GRM-05]
3. The user can import one night's Garmin sleep metrics by typing a date (default: today, the wake date of last night) and tapping Import. [GRM-09, GRM-11, GRM-23, GRM-25]
4. Too-early morning imports get a distinct "not ready yet" answer instead of a bogus zero-metric success. [GRM-18, GRM-25]
5. Imported metrics are linked to the time-overlapping acoustic night and a stage timeline (DEEP/LIGHT/REM/AWAKE) is stored for that session. [GRM-17, GRM-19]
6. Opening a morning report silently imports the night from Garmin if no data arrived yet, under a per-date retry budget. [GRM-20, GRM-22]
7. The user can import the same night's stage timeline from Health Connect (Garmin Connect as the only accepted writer) and can grant the read permission from Settings. [GRM-26, GRM-27, GRM-28]
8. Opening a morning report silently imports the Health Connect stage timeline if the session has none. [GRM-32]
9. The app makes network requests to exactly one host, only when an import runs; a repository check enforces this. [GRM-07]

### N.2.2 Flows

#### Flow: API key entry and storage
1. User types the key into a password-masked field; the Save button is enabled only while the input is non-blank (SettingsScreen.kt · `saveKey`).
2. GarminKeyStore.save requires non-blank input, trims, encrypts AES-256-GCM with an AndroidKeyStore key (alias garmin_personal_api_key, 256-bit, random IV, 128-bit tag), and stores Base64(iv + ciphertext) in SharedPreferences file garmin_secure_prefs under key personal_api_key_v1.
3. Status line updates to the masked preview (GarminKeyStore.maskedPreview — last 4 characters prefixed with an ellipsis); the input field is cleared. Save errors surface as an error message; the key value is never part of it.
4. Clear (GarminKeyStore.clear, SettingsScreen.kt · `clearKey`) removes the ciphertext and nulls the status; the button is enabled only while a key is stored.

#### Flow: manual Garmin import (Settings)
1. User edits the date field (default LocalDate.now() — the wake date of last night, SettingsScreen.kt · `importDate`); the Import button is enabled only when the text matches yyyy-mm-dd and no import is in flight.
2. SettingsScreen.kt · `importForDate` parses the date (silently ignoring unparseable input — unreachable via the UI because of the regex gate) and calls GarminImportManager.importForDate with the DEVICE zone (the picked date is "as shown on this device").
3. `importForDate` serializes on a mutex, checks GarminKeyStore.hasKey (no key → Error state), then GarminClient.fetchDay.
4. GarminClient.fetchDay exchanges the key for a bearer token (GarminClient.bearerToken, POST to the token endpoint, Authorization header "ApiKey …", Accept */* — an application/json Accept got HTTP 406 once a valid key passed auth, per the night-2 dogfood note), caches it until expiry or 5 minutes, then GETs six endpoints; each endpoint fails independently; a 401 drops the cached token and retries that endpoint once with a fresh token, and a failed re-exchange marks only that endpoint with status -1.
5. If dailySleep AND hrv are both HTTP 404 (GarminImportManager.isNotReadyNight), the import stores NOTHING and publishes NotReady (an empty replace would still re-link the session and wipe its previously imported stage timeline).
6. Otherwise, inside one Room transaction: raw JSON verbatim upserted per (source GARMIN, endpoint, date) for each 2xx non-blank body; payloads parsed (GarminImportManager.parseNightData); metrics deduplicated by type (first wins); link window = the payload's own sleep window (GarminJsonParsers.parseSleepWindow) else the day window; GarminImportManager.bestSessionOverlapping picks the link target.
7. GarminValidators.validate runs BEFORE the write; implausible metrics and invalid stage spans are dropped (raw rows keep everything). With no linked session a no-overlap warning is appended.
8. MeasurementRecorder.replaceGarminEstimates replaces the day's GARMIN rows of the incoming types over the day window (notes string "Garmin Personal API, date <date>"); when a session is linked, stale GARMIN stage timelines of other overlapping sessions are deleted, the valid stage spans replace this session's timeline (SleepStageDao.replaceForSession), and ValidityCalculator.computeAndRecord recomputes the night's validity grade INSIDE the transaction (see section 5) — a throw rolls the whole import back and keeps the Error state truthful.
9. Terminal state published: Success (metrics count, endpoints stored, per-endpoint statuses, linked session id, warnings), NotReady, or Error; CancellationException publishes Error("Garmin import cancelled.") and rethrows so the shared state never sticks at Importing; any other exception invalidates the cached token and lands in Error.

#### Flow: silent Garmin morning backfill (report)
1. ReportViewModel.reloadSuspend runs ReportViewModel.maybeBackfillGarmin after the report is built.
2. Gates: report exists, its garminStatus is not LINKED, a key is stored (GarminImportManager.canImport), no import is in flight (shared state flow), and UserPreferences.garminBackfillAllowed allows the wake date (NightDates.garminWakeDate, session time zone).
3. Import runs with the SESSION zone; afterwards ReportViewModel.markGarminAttemptBudget marks the counter the outcome drew from — `drawsNotReadyBudget` is true only for NotReady (→ UserPreferences.markGarminNotReadyRetry), every other outcome marks the general counter (→ UserPreferences.markGarminAutoRetry). The mark is NOT exclusive to the silent path: the report's own Import-this-night button (`app/src/main/java/com/sleepanalysis/ui/report/ReportViewModel.kt` · `importThisNight`) and its refresh step (`app/src/main/java/com/sleepanalysis/ui/report/ReportViewModel.kt` · `refreshMorningReport`) call markGarminAttemptBudget too. Only the Settings manual import (`app/src/main/java/com/sleepanalysis/ui/settings/SettingsScreen.kt` · `importForDate`) never marks — note this contradicts the UserPreferences KDoc ("manual imports (Settings) do not consume any budget" covers the report-side manual paths nowhere), see N.8.
4. The report is rebuilt so the imported values render.

#### Flow: retry budgets (the "2026-11-23 morning incident" gate)
1. Two independent per-wake-date counters in DataStore: garmin_auto_retry_date/ms/count (general outcomes) and garmin_not_ready_retry_date/ms/count (not-ready outcomes). Writing for a new date resets the count to 1; there is no other reset.
2. The gate (UserPreferences.GarminNotReadyBounds.backfillAllowed) always allows a date with no attempt of either kind; otherwise the budget of whichever kind was attempted LAST on that date decides.
3. General budget: 2 attempts per date with a 6 h cooldown (UserPreferences.GarminRetryBounds — the initial try plus one cooldown retry). Not-ready budget: 4 attempts per date with a 1 h cooldown (GarminNotReadyBounds). The counters can never exhaust each other's cap; the KIND of the last attempt also gates the next try, so a general failure's 6 h cooldown delays a following not-ready attempt too (bounded, accepted).

#### Flow: manual Health Connect import (Settings)
1. Availability gate: HealthConnectImportManager.isAvailable — HealthConnectClient.getSdkStatus == SDK_AVAILABLE (covers the Android 14+ built-in provider and the installed-app case). Unavailable → explanatory text and a permanently disabled Import button.
2. Otherwise a date field (default today) and an Import button gated on the same yyyy-mm-dd regex and idle state; SettingsScreen.kt · `importForHealthConnect` uses the device zone, mirroring the Garmin path.
3. HealthConnectImportManager.importForDateLocked re-checks availability and the granted permissions; missing `android.permission.health.READ_SLEEP` → NotReady(PERMISSION_MISSING), which shows a Grant button (SettingsScreen.kt · `hcPermissionLauncher`, PermissionController.createRequestPermissionResultContract). The grant imports nothing; the user re-taps Import and the manager re-checks.
4. Read window: the day window widened 6 h into the previous evening (HealthConnectImportManager.EVENING_READ_LEAD_MS) — HC's TimeRangeFilter matches records by START time, and a wake-date window returned zero records for a night starting before local midnight (found on-device 2026-11-18). The read is filtered to one data origin: com.garmin.android.apps.connectmobile (HealthConnectImportManager.garminConnectDataOrigins).
5. Each record links by its OWN span via GarminImportManager.bestSessionOverlapping (importing by day window mis-linked retrospective nights — found on-device); records with no overlapping session are counted, and if NO record links → NotReady(NO_ACOUSTIC_SESSION).
6. Inside one Room transaction: per linked session, stages map to rows (HealthConnectImportManager.buildStageRows) and replace that session's WEARABLE timeline (`replaceForSession`, schema v14 — the session's GARMIN timeline is untouched); one raw_payload summary row is upserted.

#### Flow: silent Health Connect morning backfill (report)
1. ReportViewModel.maybeBackfillHealthConnect: gates are availability, no import in flight, and HealthConnectImportManager.needsImport (the session has no WEARABLE stage rows); the wake date imports with the session zone; the report rebuilds.
2. Deliberately NO retry budget: the import is local IPC, so re-gating on needsImport already makes redundant opens cheap no-ops.

### N.2.3 State and stored data

State machines (both published on StateFlows shared by Settings and ReportViewModel):

- GarminImportState: Idle → Importing(date) → Success(date, metricsImported, endpointsStored, endpointStatuses, linkedSessionId, warnings) | NotReady(date, endpointStatuses) | Error(date, message). NotReady means "Garmin has not processed the night" (dailySleep AND hrv 404) — nothing stored. Error is terminal per attempt; cancellation publishes Error and rethrows (a stale Importing would block the backfill gate, the report buttons and Settings until app restart).
- HealthConnectImportState: Idle → Importing(date) → Success(date, stagesStored, skippedStageMinutes, linkedSessionId) | NotReady(date, NotReadyReason: HC_UNAVAILABLE / PERMISSION_MISSING / NO_ACOUSTIC_SESSION) | Error(date, message). Same cancellation discipline.

Persisted / read by this area:

- SharedPreferences file garmin_secure_prefs, key personal_api_key_v1: Base64(iv ‖ AES-256-GCM ciphertext) of the API key. AndroidKeyStore alias garmin_personal_api_key.
- DataStore keys: garmin_auto_retry_date (string, yyyy-mm-dd), garmin_auto_retry_ms (long epoch ms), garmin_auto_retry_count (int); garmin_not_ready_retry_date / garmin_not_ready_retry_ms / garmin_not_ready_retry_count (same shapes).
- raw_payload rows (table: see section 4), source GARMIN: one row per endpoint per date, payload = the response body VERBATIM (2xx non-blank only); endpoint labels are the six EP_* constants of GarminImportManager (/sleep-service/sleep/dailySleep, /sleep-service/sleep, /hrv-service/hrv, /wellness-service/wellness/bodyBattery/reports/daily, /usersummary-service/v2/dailysummaries, /usersummary-service/stats/stress/daily).
- raw_payload rows, source HEALTHCONNECT, endpoint health-connect/sleep: compact JSON summary with schema_version 1 and keys records_read, stages_stored, skipped_minutes, skipped_minutes_by_type, records_without_session, linked_session_id (omitted when null), window_start_ms, window_end_ms (HealthConnectImportManager.summaryJson).
- sleep_stage rows (schema v9/v14): source GARMIN (session-scoped, only when a session linked; canonical DEEP/LIGHT/REM/AWAKE labels, unknown vendor labels kept verbatim uppercased) and source WEARABLE (Health Connect import; AWAKE_IN_BED folded into AWAKE).
- measurement rows written via MeasurementRecorder.replaceGarminEstimates: source GARMIN, note "Garmin Personal API, date <date>"; provenance columns: see section 4. Measurement types are the 22 VENDOR_* values of MeasurementType (see section 4/5); every one of them has at least one downstream reader in domain/ui (checked by grep) — no parsed-and-unread type found.
- Platform contracts: manifest uses-permission android.permission.health.READ_SLEEP; an activity handling androidx.health.ACTION_SHOW_PERMISSIONS_RATIONALE; the Android 14+ permissions-usage intent alias with category HEALTH_PERMISSIONS (`app/src/main/AndroidManifest.xml`); ACCESS_NETWORK_STATE in `ci/permission-allowlist.txt`.
- Network posture: exactly one host, https://personal.connectapi.garmin.com (GarminClient · BASE); connect timeout 10 s, read timeout 20 s; User-Agent "SleepAnalysis/0.1 (personal; on-device sleep research)"; the key/token/bodies are never logged (only endpoint label + HTTP status). Enforced by the Gradle task `checkNetworkHosts` (`app/build.gradle.kts`), which regex-scans all main Kotlin sources for http(s) URL hosts after stripping comments, allows only personal.connectapi.garmin.com, and is wired into the check task alongside checkPermissionAllowlist, checkForbiddenTerms and checkRepoHygiene.

## N.6 Contract boundaries — what a refactor must not break

- **Persisted formats**: SharedPreferences file garmin_secure_prefs with key personal_api_key_v1 (Base64 iv ‖ ciphertext — restoring requires the same AndroidKeyStore alias garmin_personal_api_key); DataStore keys garmin_auto_retry_date / garmin_auto_retry_ms / garmin_auto_retry_count and garmin_not_ready_retry_date / garmin_not_ready_retry_ms / garmin_not_ready_retry_count; raw_payload rows with source GARMIN (endpoint labels = the six EP_* strings — they are the storage key) and source HEALTHCONNECT with endpoint health-connect/sleep and the schema_version-1 summary JSON keys of GRM-31; sleep_stage.source values GARMIN and WEARABLE (schema v9/v14 vocabulary — ReportAssembler keys on them, see sections 5–6); measurement note string "Garmin Personal API, date <date>".
- **Version strings stored with data**: summary JSON schema_version = 1; the Keystore blob has no version field — the v1 lives in the preference key name.
- **Platform contracts**: manifest android.permission.health.READ_SLEEP; androidx.health.ACTION_SHOW_PERMISSIONS_RATIONALE activity; HEALTH_PERMISSIONS permissions-usage alias (Android 14+); ACCESS_NETWORK_STATE in ci/permission-allowlist.txt; the single-host allowlist enforced by checkNetworkHosts (a new host needs a privacy review + allowlist update, per the task's own failure message).
- **Cross-area interfaces**: Settings and ReportViewModel drive both managers through their public state flows, importForDate, canImport, isAvailable and needsImport; HealthConnectImportManager reuses GarminImportManager.dayWindowMs and GarminImportManager.bestSessionOverlapping — the two importers share one linking rule (not duplicated code); MeasurementRecorder.replaceGarminEstimates is the only GARMIN measurement write path (see section 4); GarminValidators.validate and ValidityCalculator.computeAndRecord define the validity interaction (see section 5); ReportAssembler reads the WEARABLE/GARMIN stage sources and the VENDOR_* measurements (see sections 5–6); NightDates.garminWakeDate defines the wake date used by both backfills; SourceTypes.WEARABLE in MeasurementRecorder.kt documents — but does not feed — the HC source value.
- **Safety-net tests**: GarminSessionLinkTest, GarminDayWindowTest, GarminNotReadyNightTest, GarminRetryPolicyTest, GarminDayResultTest, GarminJsonParsersTest, GarminRetryBoundsTest, HealthConnectSessionLinkTest, HealthConnectStageMappingTest, ReportViewModelGarminBackfillTest.
