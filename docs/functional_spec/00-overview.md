## 0.3 End-to-end data flow

**(a) A night, from the Start tap to the stored session**
1. Start tap. `ui/home/HomeScreen.kt` · `onStartClick` obtains RECORD_AUDIO and POST_NOTIFICATIONS, then `ui/home/HomeViewModel.kt` · `startRecording` calls `monitoring/service/MonitorService.kt` · MonitorService.start: ContextCompat.startForegroundService with ACTION_START and the start source as extra.
2. Intent to command. `monitoring/service/MonitorService.kt` · `onStartCommand` returns START_STICKY and dispatches on `monitoring/service/StartIntentPolicy.kt` · `startCommandFor`: ACTION_START begins a new session, ACTION_START_NOW skips the delay, ACTION_RESUME resumes an interrupted session, ACTION_STOP stops, and a null or unknown action only surfaces an interruption.
3. Start. `monitoring/service/MonitorService.kt` · `beginRecording` promotes the service first (`startInForeground`, foreground type microphone when the mic permission is granted); it refuses while already Recording, Starting or Delayed; it fails with StartError when the mic permission is missing or free storage is below MIN_FREE_BYTES (500 MB); it refuses to open a second session over an open one (logs start_blocked_interrupted, state Interrupted); otherwise `data/repo/SessionRepository.kt` · `startSession` inserts the session row with status RECORDING.
4. Start delay. `domain/policy/StartDelayPolicy.kt` · `captureStartAtMs` gives the capture start; the state is Delayed until then (`beginCapture`) or until the user chooses start-now (`skipStartDelay`).
5. Capture. `monitoring/service/MonitorService.kt` · `beginCaptureLocked` builds the engine declared in `monitoring/audio/AudioEngine.kt` with the injected detector and clip store and starts it; `captureLoop` reads AudioRecord hops; `startHeartbeat` saves capture progress every HEARTBEAT_INTERVAL_MS (15 min) through `data/repo/SessionRepository.kt` · `saveCaptureProgress`.
6. Detection. `monitoring/audio/AudioEngine.kt` · `analyzeWindow` computes features (spectral features only when `monitoring/audio/SpectralGatePolicy.kt` · `shouldComputeSpectral` allows), `monitoring/detection/SnoreDetector.kt` · `classify` classifies the window, `monitoring/detection/EventDetector.kt` · `update` shapes events and `deliver` hands finalized events on. Under thermal throttling (`monitoring/service/ThermalPolicy.kt` · `isThrottled`) every second hop is skipped and booked in `monitoring/audio/HopSkipLedger.kt` · `skipped`.
7. Clip and event. `monitoring/audio/ClipPolicy.kt` · `decide` applies the clip budget; on a write decision the event audio held by `monitoring/audio/RingBuffer.kt` · `holdsEventAudio` is written by `data/files/ClipStore.kt` · `writeClip` (`monitoring/audio/WavWriter.kt` · `writePcm16Mono`); the service callback `monitoring/service/MonitorService.kt` · `onEventFinalized` calls `data/repo/SessionRepository.kt` · `insertEvent` (clip row and event row in one transaction); engine log lines reach `data/logs/SessionLogger.kt` · `log` through `onLog`.
8. Stop. A Home stop tap (`ui/home/HomeViewModel.kt` · `stopRecording`, after `domain/policy/NightStopPolicy.kt` · `shouldConfirmStop`) or the scheduled stop (`monitoring/schedule/ScheduledStopReceiver.kt` · `onReceive`) calls `monitoring/service/MonitorService.kt` · MonitorService.stop (a plain startService with ACTION_STOP), which runs `endRecording` with status COMPLETED.
9. Finalize. `data/repo/SessionRepository.kt` · `finalizeSession` computes aggregates and `domain/scoring/SnoreScore.kt` · `compute`, writes one measurement row per type through `data/recorder/MeasurementRecorder.kt` · `recordPhoneEstimate`, computes and stores the validity grade (`domain/validity/NightValidity.kt` · `compute`, saved by `replaceNightValidity`), finalizes the session row, registers the detector and score versions (`registerModelVersion`) and writes the report headline snapshot (`upsertReportSnapshot`).
10. Abnormal end. An engine failure or a capture stall (`monitoring/audio/CaptureStallWatchdog.kt` · CaptureStallWatchdog, DEFAULT_STALL_LIMIT_MS = 60 s) reaches `monitoring/service/MonitorService.kt` · `onCaptureError`, which runs `endRecording` with status INTERRUPTED. A process death instead leaves the session open: see INV-04.

**(b) A morning, from rows to the report screen**
1. Open. The Home last-night card, History or Trends navigates to `ui/navigation/AppNavHost.kt` · Routes.report (route report/{sessionId}); `ui/report/ReportViewModel.kt` · `reload` runs `reloadSuspend`, which calls `data/repo/SessionRepository.kt` · `buildReport`.
2. Assemble. `buildReport` reads the session, the stored validity (`domain/validity/NightValidity.kt` · `parseNotes`) and measurements, then `domain/report/ReportAssembler.kt` · `assemble` builds the report value (headline cells, hourly buckets, clip coverage, long events, stage spans, Garmin link and metrics, previous-night summary, factor entries). (The clinical-baseline rows were removed in consolidation T7.)
3. Snapshot. The screen never reads the stored snapshot. `data/repo/SessionRepository.kt` · `upsertReportSnapshot` writes the headline payload (`domain/report/ReportSnapshot.kt` · `payload`, PAYLOAD_VERSION = 1) into table `report` at finalize and on the label path; the single production read is `nightRecordFor`, which takes the snapshot's detectorVersion to decide insight eligibility.
4. Render. `ui/report/ReportScreen.kt` shows the report; the view model handles `labelEvent`, `saveMorningNotes`, `saveMorningFactors`, `playClip` and sharing (`buildShareText`, text from `domain/report/NightSummaryText.kt` · `build`). `ui/report/SessionLogScreen.kt` shows `data/logs/SessionLogger.kt` · `readSessionLog`; `ui/report/LabelingScreen.kt` lists clip-backed events for labelling.
5. Wearable refresh. `ui/report/ReportViewModel.kt` · `refreshMorningReport`, `maybeBackfillGarmin` and `maybeBackfillHealthConnect` import that night's wearable data when their gates allow and then call `buildReport` again.

**(c) Trends, validity gate, insights** (the experiments sub-flow was removed in consolidation T7)
1. Trends. `ui/trends/TrendsScreen.kt` calls `data/repo/SessionRepository.kt` · `buildTrends` (default 7 nights; skipped nights taken from the schedule-skip history), which runs `domain/report/TrendAssembler.kt` · `assemble` (keeps only `isTrendNight` sessions: zero-capture nights are excluded, never shown as quiet; flags detector / score version changes through `anyVersionChange`) and `injectMissedNights` (synthetic rows for uncovered wake dates).
2. Validity gate. `ui/insights/InsightsViewModel.kt` · `load` calls `data/repo/SessionRepository.kt` · `buildInsights` (default 14 nights); each candidate becomes a night record (`nightRecordFor`: stored NIGHT_VALIDITY grade, resolved detectorVersion, scoreVersion) and `domain/insights/PersonalBaseline.kt` · `eligibleNights` keeps only grade A or B with detector and score versions equal to `currentModelVersions`.
3. Insights. On that eligible set: `domain/insights/PersonalBaseline.kt` · `compute` (median and MAD bands), `domain/insights/SleepRegularity.kt` · `compute` (regularity index, social jetlag), `domain/insights/InsightRules.kt` · `evaluate`; `ui/insights/InsightsScreen.kt` renders the result. (The escalation-rule step was removed in consolidation T7.)
4. ~~Experiments~~ — removed in consolidation T6: ui/insights/InsightsViewModel.kt · startExperiment, domain/experiments/ExperimentTracker.kt and data/repo/SessionRepository.kt · experimentPhaseNights no longer exist; the sleep_experiment table was dropped by migration 14→15.

**(d) Garmin and Health Connect imports, linked to the acoustic session**
1. Key. `ui/settings/SettingsScreen.kt` · `saveKey` calls `data/secure/GarminKeyStore.kt` · `save` (AES/GCM with a key generated in AndroidKeyStore).
2. Garmin. `ui/settings/SettingsScreen.kt` · `importForDate` (date chosen by the user) calls `data/garmin/GarminImportManager.kt` · `importForDate` under an import mutex, then `importForDateLocked`: refuses without a stored key; `data/garmin/GarminClient.kt` · `fetchDay` (token exchange in `bearerToken`, then `httpGet` per endpoint over HttpURLConnection to BASE; retried only on 429 / 503 per `shouldRetry`, at most MAX_ATTEMPTS = 3); a night with no data yet yields NotReady (`isNotReadyNight`); otherwise `parseNightData` with the parsers in `data/garmin/GarminJsonParsers.kt` · `parseDailySleep`, then one Room transaction stores the raw payload (`rawDao.upsert`) and the parsed vendor measurements and stages.
3. Linking. `data/garmin/GarminImportManager.kt` · `bestSessionOverlapping` picks the acoustic session with the largest overlap (ties go to the later-started session; open sessions qualify); its id is stamped on the imported rows, otherwise the rows stay unlinked.
4. Health Connect. `ui/settings/SettingsScreen.kt` · `importForHealthConnect` calls `data/healthconnect/HealthConnectImportManager.kt` · `importForDate`: `isAvailable` (SDK status), a client holding the read permission for sleep-session records, `readRecords` restricted to `garminConnectDataOrigins` (the Garmin Connect app package); otherwise NotReady with HC_UNAVAILABLE, PERMISSION_MISSING or NO_ACOUSTIC_SESSION; rows come from `buildStageRows` with `mapStageType` and are linked with the same `bestSessionOverlapping`.
5. Back into the report. `ui/report/ReportViewModel.kt` · `importGarminForThisNight` (user tap) and the automatic `maybeBackfillGarmin` / `maybeBackfillHealthConnect` import the report's date and time zone and rebuild the report; `data/repo/ValidityCalculator.kt` · `garminValidityFromPayloads` and `domain/validity/GarminValidators.kt` · `validate` check the stored payloads.

Device evidence: `docs/STATUS.md` §2 records three dogfood nights (2026-11-01 to 04, all COMPLETED, including a first Garmin import) and states that battery draw over a full night has never been measured; `docs/DOGFOOD_CHECKLIST.md` lists what still needs a device. Flow (a) and the Garmin pull are therefore `device-verified` per that record; no device record was looked up for the rest.
