## N.1 What the user gets

1. A 7-night trend list: one row per recorded night with snoring minutes, share of night, longest bout, mean peak, score, clip coverage, quiet vs no-capture minutes, per-row provenance tags and validity grade, plus a minutes-scaled bar showing the week's shape. [INS-01..INS-08]
2. Nights with nothing recorded in the last-7-night span render as non-clickable synthetic "missed" rows — unless the night was skipped on purpose or is in progress. [INS-09..INS-13]
3. "Detector changed" / "score formula changed" flags when a night's model version differs from the previous night's, plus a per-screen version note. [INS-07, INS-08]
4. A personal baseline: robust median ± MAD bands per metric over the user's own eligible nights, shown with a COLLECTING / READY state. [INS-14..INS-18]
5. Sleep regularity: SRI (0–100) and social jetlag (hours), both labeled approximations. [INS-19..INS-23]
6. Up to 13 deterministic rule-based insights per night — 8 single-shot rules plus one baseline-excursion insight per metric (5 metrics) — each with confidence tier LOW or MODERATE, evidence night ids and machine-readable detail JSON — dismissible, re-showable. [INS-24..INS-33]
7. A ranked playbook of evidence-graded actions (top 3; context-only extras). [INS-34..INS-36]
8. N-of-1 experiments: start a 7-night experiment on an action, watch honest usable/excluded/missing counts, get an automatic verdict against the user's own start band, optionally confirm with an A-B-A return-to-baseline phase, keep or abandon. One ACTIVE at a time. [INS-37..INS-45]
9. A clinician-escalation card over the same eligible nights: acoustic arm (3 consecutive snoring-heavy nights) plus a once-collected STOP-BANG-derived self-report. [INS-46..INS-48]

### N.2.2 Flows

#### Flow: build the 7-night trend
1. TrendsViewModel.init → SessionRepository.buildTrends(skippedDays = prefs.scheduleSkipHistoryDaysNow()) — one pull, no observation.
2. SessionRepository.buildTrends → filter sessions with TrendAssembler.isTrendNight (finalized, status COMPLETED / RECOVERED / INTERRUPTED, ≥ 1 PROCESSED window), sort by startedAt, take last 7.
3. TrendAssembler.assemble → per night: stored measurement rows (SNORE_TIME → minutes, SNORE_SHARE_OF_NIGHT → %, SNORE_SCORE, NIGHT_VALIDITY grade), label-aware events via SnoreMath.eventsCountingAsSnore (bout / mean peak / clip coverage / detector version), quiet_gap rows split by QUIET vs UNCAPTURED kind, Garmin rows joined by wake-date window (VENDOR_SLEEP_SCORE / VENDOR_DEEP_SLEEP / VENDOR_REM_SLEEP).
4. Detector/score versions compare to the previous kept night; a change flag needs BOTH sides known.
5. TrendAssembler.injectMissedNights → synthetic rows for uncovered wake dates of today−6..today unless skipped or in progress; TrendsScreen renders, guarding clicks on sentinel id −1.

#### Flow: build the insights report
1. InsightsViewModel.load → SessionRepository.buildInsights(maxNights = 14): last 14 trend-eligible nights → nightRecordFor → InsightRules.NightRecord records.
2. SessionRepository.currentModelVersions resolves registry DETECTOR/SCORE versions (fallbacks MODEL_VERSION / SnoreScore.FORMULA_VERSION); PersonalBaseline.eligibleNights filters grade A/B + exact version match, keeps last 14 — ONE eligibility decision shared by baseline, rules, escalation card.
3. PersonalBaseline.compute builds bands; SleepRegularity.compute needs the per-night Garmin window.
4. InsightRules.evaluate(EvalContext) runs R1–R9 over eligible nights; Playbook.rank(insights, dismissedRules) ranks actions; EscalationRule.evaluate(eligibleRecords, selfReport) builds the card.

#### Flow: N-of-1 experiment lifecycle
1. Start: InsightsViewModel.startExperiment (mutex-guarded) → ExperimentTracker.startExperiment — ONE Room transaction checks SleepExperimentDao.active (reject ACTIVE_EXISTS), READY baseline (reject BASELINE_COLLECTING), band present (reject NO_BASELINE_BAND), inserts row status ACTIVE with the baseline band JSON captured at start, plannedNights clamped 5..30.
2. Progress: ExperimentTracker.progress → phase nights from SessionRepository.experimentPhaseNights (since startedAt, eligibility re-filtered, last 60) → ExperimentMath.evaluatePhase partitions usable / confound-excluded / missing-value.
3. Auto-finalize on every Insights load: ExperimentTracker.refreshActiveVerdict → at ≥ planned usable nights SleepExperimentDao.finish (ACTIVE → DONE with the verdict JSON).
4. A-B-A: user reverts behaviour, taps confirm → ExperimentTracker.startConfirmPhase re-activates the SAME DONE row (SleepExperimentDao.beginConfirmPhase, transactional single-ACTIVE check) → after ≥ planned usable nights SleepExperimentDao.finishConfirm upgrades confidence to MODERATE if the phase-2 median returned inside the start band.
5. Keep: ExperimentTracker.keepVerdict rewrites resultJson with kept=true (verdict card stops rendering); a Keep survives the confirm finalize rebuild.
6. Abandon: InsightsScreen abandon buttons (active and verdict cards) → InsightsViewModel.abandonExperiment → ExperimentTracker.abandon → SleepExperimentDao.abandon (status = 'ABANDONED' WHERE status != 'ABANDONED') — terminal, allowed from ACTIVE or DONE.

#### Flow: escalation evaluation
1. InsightsViewModel.load reads UserPreferences.escalationSelfReportNow() (four DataStore keys, answered flag).
2. EscalationRule.evaluate: acoustic arm = longest run of consecutive eligible nights with snoreShare > 0.25 AND longestBout > 10 min (strict); self-report arm = any YES.
3. EscalationCard renders triggered arms or the collecting copy; SelfReportSection collects/edits the three S/O/T questions once.

### N.2.3 State and stored data

- **`sleep_experiment` table (schema v13)** — SleepExperimentEntity columns: `id`, `hypothesisRuleId`, `playbookActionId`, `metric`, `startedAt`, `plannedNights`, `status` (TEXT: ACTIVE / DONE / ABANDONED — plain constants, not a Room enum), `baselineStatsJson`, `resultJson`, `confirmPhaseJson`, `createdAt`. Index on `status`. No FK — outlives sessions.
- **`baselineStatsJson`**: `{"metric","median","mad","low","high"}` (baseline band captured at start).
- **`resultJson`** (`schema_version:1`): `change_detected`, `direction` (UP/DOWN/null), `confidence` (LOW/MODERATE), `phase_median`, `robust_z`, `phase_nights`, `planned_nights`, `used_night_ids`, `excluded_night_ids`, `kept`; after a confirm phase also `confirmed`, `confirm_median`, `confirm_returned_to_band`.
- **`confirmPhaseJson`** (`schema_version:1`): `phase:"CONFIRM"`, `started_at`; finalized adds `phase2_median`, `returned_to_band`, `confirmed`, `confidence`.
- **Status machine**: ACTIVE → DONE (finish, guarded status='ACTIVE') → ACTIVE again (beginConfirmPhase, guarded status='DONE') → DONE (finishConfirm, guarded status='ACTIVE' — an ABANDONED row can never be resurrected by an in-flight finalize); ABANDONED from ACTIVE or DONE via abandon (WHERE status != 'ABANDONED'), terminal.
- **DataStore keys** (UserPreferences): `insights_dismissed_rules` (string set of rule ids), `escalation_self_report_answered`, `escalation_snoring_loud`, `escalation_witnessed_pauses`, `escalation_daytime_sleepiness`.
- **Insight detailJson** (per-rule keys): hand-built compact JSON, stable key order (rule-specific keys listed in the rule KDocs); shown expanded, never rendered as a measurement.
- Trend rows are computed, not persisted; the persisted inputs are the `measurement`, `acoustic_event`, `audio_clip`, `quiet_gap`, session and `sleep_experiment` rows (see sections 4–6).

## N.6 Contract boundaries — what a refactor must not break

- **Persisted formats**: `sleep_experiment` table and column names (schema v13, `status` TEXT with ACTIVE/DONE/ABANDONED); `baselineStatsJson`, `resultJson` (schema_version 1, all keys listed in N.2.3), `confirmPhaseJson` key names; DataStore keys `insights_dismissed_rules`, `escalation_self_report_answered`, `escalation_snoring_loud`, `escalation_witnessed_pauses`, `escalation_daytime_sleepiness`; the insight detailJson key names (rule ids and copyKey strings are drift-tested against docs/INSIGHTS.md and strings.xml by `InsightsDocTest`).
- **Version strings stored with data**: the event / SNORE_SCORE `modelVersion` values feed the eligibility comparison and the trend flags — a refactor must keep comparing against the registry's current DETECTOR/SCORE versions, including the null-matches-null rule.
- **Platform contracts**: none introduced here (no manifest entries, permissions or notifications).
- **Cross-area interfaces**: validity grading (see section 5) supplies NIGHT_VALIDITY grades — eligibility is grade A / B here; experiment table persistence and DAO guards (section 4); report numbers and SnoreMath bout/union math (sections 5–6); MissedNightPolicy shares the missed-night semantics with the Home banner (section 3); DailyFactor keys (factor logging area) feed the confound exclusion; ui/home/HomeViewModel reads ExperimentTracker.activeExperiment + progress for the Home chip.
- **Safety-net tests**: `TrendAssemblerTest`, `PersonalBaselineTest`, `SleepRegularityTest`, `InsightRulesTest`, PlaybookTest, EscalationRuleTest, ExperimentMathTest, `InsightsDocTest`, `EvidenceBaseDocTest` — run all after touching this area.
